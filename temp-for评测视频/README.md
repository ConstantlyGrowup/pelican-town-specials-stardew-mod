# JEV 文本评测视频演示

独立本地网页：用 120 道菜、360 项现实原料构成 720 条“现实原料 ↔ 游戏候选原料”判断题。可先点击“先测 32 题”检查整条评测链路，再点击“测全部 720 题”正式运行。两种按钮都要经过计费确认；页面打开时不会发送请求。

## 启动

在仓库根目录安装现有后端开发依赖后运行：

```powershell
python 'temp-for评测视频/prepare_cases.py'
python 'temp-for评测视频/server.py'
```

打开 <http://127.0.0.1:8765/>。浏览样本、表格与历史记录不需要 Key。实际点击“开始评测”前，需要在**运行服务的进程**中提供 `OPENROUTER_API_KEY`；请通过环境变量设置，勿在网页输入或写入仓库。服务启动后再修改环境变量时，重新启动服务使其可见。网页只绑定本机 `127.0.0.1`。


数据准备脚本若发现已有冻结数据，会核对并拒绝覆写不一致文件。当前样本哈希、来源哈希和规则在 `data/manifest.json`；具体每条标签与依据在 `data/cases.jsonl`。首次准备后，真实运行前请核对负例构造规则和样本范围。

32 题试跑从同一冻结集合中按固定顺序抽取“合理”与“不合理”各 16 题，覆盖 32 道不同菜品；服务端 `/api/bootstrap` 返回其独立选择摘要和 SHA-256。每次试跑选到相同题目。它只是先检查请求、进度、判分、费用与导出是否正常；32 题结果不会并入 720 题准确率，也不会参与 720 题的串行/并发速度倍数。

## 录屏流程

1. 首屏核对模型、题数和数据说明。可先选“先测 32 题”并确认计费，最多发送 32 个 JEV 请求；观察链路完整后，再选“测全部 720 题”。并发可选 1、8、32、64、128 或 720，默认 64；32 题试跑的实际同时请求数最多为 32。单次超时 45 秒，不自动重试。720 档是压力测试，不保证耗时最短；上游限流、429、超时会如实计入失败。
2. 观察 720 格全量进度图、时间和逐题详情表。点击任意格可查看对应题目；表格一次显示 8 条供细读，不代表只处理 8 条。选“不合理”且参考答案也为“不合理”计作判断正确。
3. 结束后展示固定全集准确率、正负例识别率、失败数、实际费用字段覆盖数和总耗时；导出 JSON 可复算。
4. 若要演示并发提速，在相同数据和实际模型版本下另运行一次“并发 1”。两次真实 run 的耗时对照才可称为本次加速比。两轮合计最多 1440 个请求，费用分别统计。应同时展示失败数，避免把限流导致的缩短误称为提速。

浏览器刷新后会连接最近一次运行，不重新发请求。运行中点停止仅阻止后续派发，已发出的请求仍可能完成并计费。运行完成后再点开始会开启一个新的真实 run。`runs/` 存放每轮原始记录，默认 Git ignored；导出按钮下载含 manifest 和逐项结果的 JSON。无真实 run 时，页面不显示预制成绩。

## 数据解释

正例来自已冻结的项目 Gold ID。负例是事前固定、明显跨类别的对应错误：原料 Gold 为鱼时选面粉或番茄，否则选鲑鱼或鳀鱼。它们覆盖 360 项原料，但属于**明确错误的诊断集**，不能把本轮准确率推广到近义替代、翻译细节或真实用户总体。`Wheat Flour` 的英文原意优先于游戏中文显示“大麦粉”。本任务准确率衡量的是 **JEV 判断与这些参考标签是否一致**，不是 RAG 原料映射本身的准确率。

页面使用 OpenRouter `typesafe/jev-1.13` 的 Decisions API。每个请求只传当前菜名、现实原料、当前游戏候选原料及固定判定规则；Gold、标签依据和旧新链路标识留在本地。JEV 只提供固定选项和接口置信度，不提供解释理由。总费用只累计响应中实际报告的 `usage.cost`；缺失费用字段时会显示覆盖数，不把未知金额当 0。
