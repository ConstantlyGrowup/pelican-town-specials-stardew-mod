## 背景

用户真实环境运行 Ask Gus 双图 EDIT 时，Provider 报：`status_code=400, invalid image size: total pixels must not be less than 655360 (got "752x672")`（752x672=505,344 < 655,360）。用户给出两方案（LANCZOS 放大 或 拦截）由实施者选择。

**方案选定**：放大为主（LANCZOS 升到满足下限的最小 16 倍数尺寸，保持宽高比），极端比例无法同时满足「最小像素 + 长边 ≤2048」时受控拦截兜底。

## 实现（commit `8f36b6d`，4 文件 +107/-10）

- **`images/vision_input.py`**：新增 `VISION_MIN_PIXELS = 655_360` 与 `_ceil_align_edge`（向上取整 16 倍数，min 16）；`downscale_for_vision` 新增 `min_pixels` 参数——缩放+16 倍数对齐后若总像素 < 下限，`upscale = sqrt(min_pixels / (w*h))` 两轴 `_ceil_align_edge` 放大（乘积必然 ≥ 下限）；放大后长边将超 `max_side`（如 16x2048 极端比例）抛 `ValueError`。
- **`generation/orchestrator.py`**：新增 `_prepare_vision_input(data)` 包装 `downscale_for_vision`，`ValueError` 转受控 `PTS_IMAGE_INPUT_UNSUPPORTED`（422, retryable=False, details={minPixels}）；DISH_ANALYSIS 与 PREVIEW 两处调用统一改用（同一约束服务 vision chat 与双图 EDIT，Yibu 探测亦记录 ≥655,360）。
- **测试（TDD 红→绿）**：`test_small_image_is_upscaled_to_min_pixels`（640x480→944x704=664,576）、`test_small_edit_input_upscaled_to_min_pixels`（752x672→864x768=663,552，复现真实失败）、`test_extreme_ratio_cannot_meet_min_pixels_raises`（16x2048→ValueError）、`test_prepare_vision_input_rejects_impossible_ratio_controlled`（受控 AppError）；原 4032x2689/990x1051（≥下限不放大）与 harness 相对断言不受影响。
- round-0 修复：`AppError.details` 必填补上；`_ceil_align_edge` 签名 float→int（mypy arg-type）。
