# 原料 RAG 对比：人审简版

这份报告只看“给定一道菜及其三项现实原料后，系统能否找到合理的星露谷原版原料”。它比较旧匹配链路与显式启用的本地 RAG；不包含照片识别、上游原料生成，也不是线上用户的实际成功率。当前产品默认仍是旧链路。

## 测试范围

- 较早一批 **24 道菜、72 项原料**，扩样一批 **96 道菜、288 项原料**；中英文菜名均不重复，因此按用户确认的“不同菜即可合并”口径，共计 **120 道菜、360 项原料**。每项都预先指定了至少一个游戏目录中的可用对应物，所以理论上都不需要兜底。
- 两批有 **30 个原料 query 重复**，这是不同菜复用同种食材，并非重复菜。合并数字是 120 道不同菜的描述性结果，不表示 360 项原料语义完全独立。
- 两侧使用相同菜品、现实原料和游戏目录。逐项合理性由 JEV 判定；针对游戏物品 `246` 英文名 `Wheat Flour`、中文显示名 `大麦粉` 的歧义，按用户确认的规则统一事后修正：现实 `Wheat Flour`／`小麦粉` 非兜底映射到 `246` 算合理。24 菜中两侧各修正 3 项；96 菜中旧链路修正 12 项、RAG 修正 15 项。原始 JEV 判定和冻结输入没有修改。

## 核心结果（120 道不同菜，事后修正口径）

| 指标与通过条件 | 旧链路 | RAG |
|---|---:|---:|
| **全菜正确**：一道菜的 3 项都非兜底且合理才通过 | **65/120（54.17%）** | **92/120（76.67%）** |
| **单原料合理**：一项非兜底且合理就通过；分母包括兜底项 | **282/360（78.33%）** | **328/360（91.11%）** |
| **Top 5 召回命中**：候选中至少有一个预设可接受原料 | 304/360（84.44%） | 346/360（96.11%） |
| **最终命中预设原料**：实际选中可接受 ID，且不是兜底 | 264/360（73.33%） | 318/360（88.33%） |
| **非兜底覆盖**：最终找到目录原料而不是走兜底 | 314/360（87.22%）；兜底 46 项 | 360/360（100%）；兜底 0 项 |

分开看，24 菜为 **17/24 → 21/24**，96 菜为 **48/96 → 71/96**；合并后 RAG 多通过 **27 道**，没有由通过变为不通过的菜。Top 5 命中高于最终命中，说明即使已找到合适候选，最终选择仍有改进空间。旧链路的 46 次兜底不是“游戏没有该原料”：这些项在冻结目录中都有预设的可用对应物。兜底数量在此只帮助解释召回覆盖，不作为单独的产品改善 KPI。预设原料命中与 JEV 的语义合理判定是两种不同检查，不能互相替代。

## 耗时

每项原料的耗时包括候选检索／构建及最终映射，不包括 JEV 评测调用；在本机单进程离线运行，不能等同于打包版用户等待时间。

| 每项原料映射耗时 | 旧链路 | RAG |
|---|---:|---:|
| 中位数 | 1.089 毫秒 | 6.403 毫秒 |
| 95% 项目不超过 | 1.589 毫秒 | 8.833 毫秒 |
| 两批最大值 | 3.005 毫秒 | 1639.913 毫秒 |

RAG 的最大值包含首次懒加载模型和索引；日常较有代表性的单项耗时可参考中位数与 95% 分位值。

## 结果应如何理解

这是**观察结果后的翻译歧义修正分析**，不是预先规定的 JEV 主指标。原始 JEV 全菜结果为 24 菜 **14/24 → 18/24**、96 菜 **41/96 → 59/96**，简单合计 **55/120 → 77/120**；原判均保存在[24 菜技术报告](M14_TASK66_INGREDIENT_RAG_COMPARISON.md)、[96 菜技术报告](M14_TASK66_1_EXPANDED_HOLDOUT.md)和原始记录中。两批都是人工策划测试集，存在重复原料 query；不能将合并比例直接解释为真实用户群体的成功率。
